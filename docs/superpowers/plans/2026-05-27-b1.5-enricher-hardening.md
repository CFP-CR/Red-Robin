# B1.5 — WM Enricher Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden the Plan-B `WorkingMemoryEnricher` for production so B1+B1.5 merge as one PR — give it the exact command behind each output (via the CS `$5` correlation id), bound its LLM concurrency, filter Red Robin's own console annotations, ground host extraction OS-agnostically, and dedup findings in the single-writer merge.

**Architecture:** The enricher is an async `EventBus` consumer: it sees `beacon.command_output` (and now `beacon.command_input`) bus events, recovers the originating command, strips self-annotations, runs an enrich-by-default trigger, chunks the output, calls a Haiku-class LLM per chunk under a shared semaphore, parses JSON deltas, and publishes a `working_memory.deltas` event that the reducer (single writer) merges into `working_memory.json`. The `.cna` adapter and the v0.1 wire schemas gain an optional `correlation_id`; everything downstream of `_envelope_to_bus_event` already passes the full event body through as the bus `payload`, so no extra plumbing is needed.

**Tech Stack:** Python 3.12, asyncio EventBus, pydantic-settings, Anthropic SDK, pytest; Cobalt Strike Aggressor (.cna, smoke-only).

**Discrepancy note (reality vs spec — full detail in "Notes for the auditor"):**
- The spec (§4) describes the enricher caching `correlation_id → raw command`. The wire `beacon.command_input` event carries BOTH a `command` (first token) and a `raw` (full command line). The enricher's existing `_enrich` reads `payload.get("command")`, and `should_enrich`/the LLM both want the full command. The cache stores the **`raw`** value (the full command line, e.g. `shell systeminfo`) since that is the richest signal, falling back to `command` then `""`. This is consistent with the spec's "raw command" wording.
- The reducer dispatches `working_memory.deltas` → `repo.apply_deltas`. Findings dedup therefore lands in `apply_deltas` exactly as the spec says (Area 5). The `Finding` dataclass docstring currently states findings are "never deduplicated" — that line is updated in Task 8.
- mypy is configured (`pyproject.toml`) to type-check **only** `redrobin/domain` + `redrobin/application` (infrastructure is `disallow_untyped_defs = false`). So `enricher.py`, `sanitize.py`, `events.py` are strictly gated; `anthropic_client.py` + `working_memory_repo.py` are not strict-gated but must stay typed.

```python
"""Strip Red Robin's own console annotations from beacon output before enrichment.

The ``.cna`` gate ``blog``s lines like ``[Red Robin] novel pattern — Layer B
reviewing async`` into the beacon's console, which Cobalt Strike then echoes back
into the output stream the enricher sees. Enriching those lines produces junk
findings (``novel_pattern`` / ``unusual_activity``) and extracts "Red Robin" as a
tool. This helper drops any line whose first non-whitespace content is the
self-annotation prefix, so only genuine command output reaches the LLM.

Defensive (enricher-side). The ROOT fix — stop the ``.cna`` from emitting the
annotation into the output stream at all — is the separate ``.cna`` plan.
"""

from __future__ import annotations

import re


def strip_self_annotations(output: str, *, prefix: str) -> str:
    """Return ``output`` with every line that starts (after optional leading
    whitespace) with ``prefix`` removed. ``prefix`` is matched literally
    (``re.escape``) so regex metacharacters in it (e.g. the brackets in
    ``[Red Robin]``) are not interpreted. Line structure of the surviving
    lines is preserved; the result is joined with ``\\n`` (a sole trailing
    newline is not re-added)."""
    pattern = re.compile(r"^\s*" + re.escape(prefix))
    kept = [line for line in output.splitlines() if not pattern.match(line)]
    return "\n".join(kept)


__all__ = ["strip_self_annotations"]
```

```python
from __future__ import annotations

from redrobin.application.enrichment.enricher import WorkingMemoryEnricher
from redrobin.application.event_bus import EventBus


def _make_enricher() -> WorkingMemoryEnricher:
    return WorkingMemoryEnricher(
        bus=EventBus(),
        llm=None,
        denylist=["ls"],
        min_output_chars=8,
        chunk_max_chars=16000,
        enabled=True,
    )


def test_exact_match_by_correlation_id():
    e = _make_enricher()
    e._remember_command({"bid": "B-1", "raw": "shell systeminfo", "correlation_id": "18ff"})
    assert (
        e._recover_command({"bid": "B-1", "output": "x", "correlation_id": "18ff"})
        == "shell systeminfo"
    )


def test_correlation_id_is_evicted_on_match():
    e = _make_enricher()
    e._remember_command({"bid": "B-1", "raw": "shell whoami", "correlation_id": "abcd"})
    assert e._recover_command({"bid": "B-1", "correlation_id": "abcd"}) == "shell whoami"
    # Second lookup of the same correlation id no longer hits the corr cache; it
```

```python
    def _remember_command(self, payload: dict[str, Any]) -> None:
        """Cache the command behind a future output. Prefers the full ``raw``
        command line, then the first-token ``command``, then ``""``. Keyed by
        ``correlation_id`` (exact, FIFO-bounded) with a per-``bid`` last-command
        fallback for outputs that arrive without a correlation id."""
        command = str(payload.get("raw") or payload.get("command") or "")
        corr = payload.get("correlation_id")
        bid = payload.get("bid")
        if bid is not None:
            self._cmd_by_bid[str(bid)] = command
        if corr is not None:
            corr_key = str(corr)
            self._cmd_by_corr[corr_key] = command
            self._cmd_by_corr.move_to_end(corr_key)
            while len(self._cmd_by_corr) > self._CORR_CACHE_MAX:
                self._cmd_by_corr.popitem(last=False)  # evict oldest (FIFO)

    def _recover_command(self, payload: dict[str, Any]) -> str:
        """Recover the command that produced this output: exact correlation_id
        lookup (popped on hit so the entry doesn't leak) → per-bid last command
        → ``""`` (degraded — pre-correlation-id CS, or input not yet seen)."""
        corr = payload.get("correlation_id")
        if corr is not None:
            cmd = self._cmd_by_corr.pop(str(corr), None)
            if cmd is not None:
                return cmd
        bid = payload.get("bid")
        if bid is not None:
            cmd = self._cmd_by_bid.get(str(bid))
            if cmd is not None:
                return cmd
        return ""
```

## Notes for the auditor

**Reality-vs-spec discrepancies found while reading the code (all handled in the plan):**

1. **`command` vs `raw` on `beacon.command_input`.** The wire event carries BOTH `command` (the first token, e.g. `shell`) and `raw` (the full command line, e.g. `shell systeminfo`). The spec says "cache `correlation_id → raw command`". The plan caches `raw` (falling back to `command`, then `""`) because the full command line is the richest signal for both `should_enrich` (the denylist matches the inner verb of `shell ls -la`) and the LLM context. The existing `_enrich` read `payload.get("command")`; Task 5 changes it to prefer the recovered command and only falls back to `payload.get("command")`/`cmd` when the recovery caches are empty (preserving existing fixture/trace behavior where a `command` is supplied directly on the output event).

2. **Schema MUST precede the `.cna` (additionalProperties).** `events_router.py:ingest` validates every event against its per-type schema with `additionalProperties:false`, and `_envelope_to_bus_event` passes the whole event body through as the bus `payload`. So the schema change (Task 3) is a hard prerequisite for the `.cna` emitting `correlation_id` (Task 9) — otherwise the daemon 400s every command event. Task 3 is ordered before Task 9 and this is called out in both tasks. As a bonus, because the body passes straight through, NO extra plumbing is needed for `correlation_id` to reach the enricher's `payload` — it arrives automatically once it's on the wire.

3. **`correlation_id` is genuinely new on these two schemas.** A grep shows `correlation_id` is used elsewhere on the bus (the `opsec.verdict` payload the verdict pipeline publishes, and the `command.vet` HTTP request body) but it is NOT a field on ANY `protocol/schemas/v0.1/events/*.schema.json` today, and there is no name clash with the `beacon.command_*` events. Adding it is purely additive.

4. **No existing round-trip test for `BeaconCommandOutputEvent`.** `tests/unit/test_domain_events.py` only round-trips `BeaconCommandInputEvent` against the schema. Task 3 adds explicit schema-validation tests for BOTH events' new `correlation_id` (the output event's first such test).

5. **Findings dedup lives in `apply_deltas`, not the legacy `append_finding`.** The reducer routes `working_memory.deltas` (the enrichment path) → `apply_deltas`; the regex path uses `append_finding` (still append-only, retired in B2). The spec's Area 5 is the enrichment merge, so Task 8 dedups `apply_deltas` only and updates the `Finding` docstring (which previously claimed findings are "never deduplicated"). The legacy `append_finding` docstring is intentionally left append-only.

6. **mypy scope.** `pyproject.toml` runs strict mypy on `redrobin/domain` + `redrobin/application` ONLY (`redrobin.infrastructure.*` has `disallow_untyped_defs = false`). So the strictly-gated edits are `sanitize.py`, `enricher.py`, `events.py`; the infra edits (`anthropic_client.py`, `working_memory_repo.py`) are not strict-gated but are kept fully typed. The CI gate command in Task 10 (`mypy redrobin/domain redrobin/application`) matches the operator's required gate exactly.

7. **The semaphore is created in Task 4 but used in Task 6.** To keep each task bite-sized (Task 4 = recovery machinery + new `__init__`; Task 6 = concurrency), `self._sem = asyncio.Semaphore(max_concurrency)` is initialized in the Task 4 `__init__` rewrite and first consumed by Task 6's `_extract_chunk`. This is flagged in both tasks and re-verified in Task 10 Step 3 so a reviewer doesn't mistake it for dead code at any intermediate commit (it is dead for exactly one commit — Task 4's — which is an accepted TDD intermediate state).

**Smoke-only `.cna` caveat (restated):** Task 9 has no pytest CI — Aggressor cannot run in this repo's CI. Its acceptance is the operator live-beacon smoke (Task 9 Step 4 + the spec §11 acceptance list). The Python schema/events halves ARE unit-tested (Task 3). The `.cna` edits are additive (append `correlation_id` only when non-empty) and reversible; the working gate logic is untouched. `$5` is undocumented and could change across CS versions — mitigated by the per-`bid` last-command fallback (Task 4), which degrades gracefully (never crashes) when `correlation_id` is absent or unknown.
